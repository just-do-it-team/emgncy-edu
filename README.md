# emgncy-edu

## Демо-стенд

Приложение работает на реальном бэкенде в части входа: логин и пароль проверяет сервис
авторизации, роль приходит вместе с профилем. Кабинет преподавателя, разбор попытки и
разделы «Прогресс» и «Материалы» пока показывают моковые данные. Сессия живёт час и после
перезагрузки страницы не восстанавливается — потребуется войти заново.

В базу стенда засеяны три учётные записи (миграция `0003`):

| Логин | Роль |
|---|---|
| `yWJJ9_z` | преподаватель |
| `yWJJ9_y` | обучающийся |
| `yWJJ9_x` | обучающийся |

Пароли в репозитории не хранятся: в миграции лежат только PBKDF2-хеши, восстановить из них
исходные значения нельзя. Пароли выдаёт бэкенд-разработчик.

## Локальный запуск

После клонирования репозитория:

```sh
cp frontend/.env.example frontend/.env
```

Затем заполните в `frontend/.env` два адреса стенда:

| Переменная | Что указывает |
|---|---|
| `VITE_CARD_API_PROXY_TARGET` | адрес card-api, порт 8080 |
| `VITE_AUTH_API_PROXY_TARGET` | адрес auth-api, порт 8084 |

Адреса выдаёт бэкенд-разработчик; в репозитории они не хранятся.

Пока переменные пусты, Vite **не поднимает dev-прокси**, и запросы к `/student-api` и
`/auth-api` обрабатывает сам дев-сервер — он отвечает на них `404`, потому что таких
файлов в проекте нет. Выглядит это как «API не отвечает», хотя до бэкенда запрос не
доходит вовсе.

`frontend/.env` читается один раз при старте: **после правки дев-сервер нужно
перезапустить**, перезагрузки страницы недостаточно.

```sh
cd frontend
npm install
npm run dev
```

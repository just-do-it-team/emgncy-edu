# Воспроизведение попытки: расшифровка звонка и таймлайн карточки

Статус: черновик
Потребитель на фронте: `entities/call-transcript`, `entities/card-timeline`, экран разбора попытки
Связанные файлы фронта: `frontend/src/shared/api/contracts/call-transcript.ts`,
`frontend/src/shared/api/contracts/card-timeline.ts`,
`frontend/src/entities/call-transcript/api/*`, `frontend/src/entities/card-timeline/api/*`

## Назначение

Преподавателю нужно видеть, **что сказал заявитель и что в этот момент делал оператор** — на
одной оси времени. Две ручки дают две половины картины: расшифровка — речь, таймлайн — действия
в карточке. По ним читается порядок работы: заявитель назвал адрес, оператор записал другой, и
между этими моментами не было ни одного переспроса.

Две ручки, а не одна, потому что их источники независимы: расшифровка складывается из
`audio_message` голосового конвейера, таймлайн — из `training_action` и истории карточки. Бэкенд
может отдать одну раньше другой, и фронт переключит её на живой запрос отдельным флагом.

Сейчас обе на моках: `VITE_MOCK_CALL_TRANSCRIPT` и `VITE_MOCK_CARD_TIMELINE`, по умолчанию
включены.

## Ручки

### GET /api/v1/training-sessions/{training_session_id}/call-transcript

Назначение: расшифровка входящего звонка попытки.
Отношение к существующему: **новая**. Ближайшее —
`GET /api/v1/workspaces/{workspace_id}/incoming-calls/{call_id}/audio-messages`, но она требует
`workspace_id` и `call_id`, не отдаёт смещения от начала звонка и разбросана по сообщениям STT и
TTS-сегментам.
Доступ: `TEACHER` — попытки своих назначений; `ADMINISTRATOR` — любые; `STUDENT` — только свои
завершённые попытки.

Успешный ответ: 200

| Поле | Тип | Описание |
|---|---|---|
| `call_id` | uuid | входящий звонок попытки |
| `started_at` | datetime | момент ответа на звонок; **ноль оси времени** |
| `duration_ms` | int | длительность звонка до отбоя |
| `utterances` | array | реплики по возрастанию `offset_ms` |

Элемент `utterances`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid | идентификатор `audio_message` или TTS-сегмента |
| `speaker` | enum | `CALLER` — заявитель, `OPERATOR` — обучающийся |
| `input_mode` | enum | `VOICE` — сказано голосом, `TEXT` — набрано текстом и озвучено |
| `offset_ms` | int | начало реплики от `started_at` |
| `duration_ms` | int | длительность звучания |
| `text` | string | текст реплики |
| `audio_url` | string \| null | адрес аудио; `null`, если озвучить не удалось |
| `stt_confidence` | number \| null | уверенность распознавания 0..1; заполнена только у распознанной речи оператора (`OPERATOR` + `VOICE`) |

Реплики заявителя генерирует LLM и озвучивает TTS, поэтому у них `stt_confidence` всегда `null`.
Реплика оператора в режиме `TEXT` озвучена TTS через `tts-messages` — аудио у неё есть, а
распознавания нет.

Ошибки: 404 — попытки нет или в ней не было входящего звонка; 403 — чужая попытка;
409 — попытка не завершена.

### GET /api/v1/training-sessions/{training_session_id}/timeline

Назначение: действия в карточке на той же оси времени, что и расшифровка.
Отношение к существующему: **новая**. Ближайшее — `GET /api/v1/training-sessions/{id}/actions`, но
оно отдаёт абсолютные моменты, а не смещения, и не сводит действия к изменениям полей.
Доступ: как у расшифровки.

Успешный ответ: 200

| Поле | Тип | Описание |
|---|---|---|
| `utterances_offset_base` | datetime | момент, от которого считаются `offset_ms` событий. **Обязан совпадать с `started_at` расшифровки** — иначе оси не сходятся |
| `events` | array | события по возрастанию `offset_ms` |

Элемент `events` — общий набор полей, из которых у каждого вида заполнены свои:

| `kind` | Обязательные поля | Смысл |
|---|---|---|
| `CARD_OPENED` | — | карточка раскрыта |
| `FIELD_SET` | `path`, `value`; `previous` — `null`, если поле было пустым | поле карточки изменено |
| `SERVICE_ADDED` | `service_id`, `card_service_id` | служба добавлена в карточку |
| `STATUS_CHANGED` | `card_service_id`, `from`, `to`; `comment` — если требуется | статус реагирования службы изменён |
| `DECISION` | `card_service_id`, `decision` (`ACCEPTED` \| `REJECTED`); `comment` — обязателен при `REJECTED` | решение службы по карточке |

`from` и `to` принимают значения автомата статусов реагирования, см.
`docs/domain/response-status.md`. `path` — путь поля карточки в формате `discrepancies[].path`
из результата попытки: `incident_address`, `description`, `victims_count`,
`features.event_kind_id` и т.д.

Фронт считает отсутствие обязательного для вида поля нарушением контракта и показывает ошибку
загрузки, а не молча пропускает событие.

Ошибки: как у расшифровки.

## Пример

Звонок о задымлении квартиры, `1050102 · жилой дом / квартира / дым → задымление: квартира`.
Полные данные — в моках `call-transcript.mocks.ts` и `card-timeline.mocks.ts`; здесь фрагмент,
на котором строится разбор:

```
15 900 мс  CALLER    «Ленинский проспект, дом 14, второй подъезд, седьмой этаж, квартира 58.»
24 100 мс  OPERATOR  «Открытый огонь видите или только дым?»
34 200 мс  CARD_OPENED                                     — позже норматива 30 с
35 600 мс  OPERATOR  «Внутри кто-нибудь остался?»
47 800 мс  OPERATOR  TEXT «Не приближайтесь к дыму, выходите наружу.»
57 800 мс  FIELD_SET incident_address = «…Ленинский проспект, д. 41…»
151 300 мс DECISION  ACCEPTED                              — в пределах норматива 180 с
```

Дом 14 и дом 41 — перестановка цифр на слух; по Ленинскому проспекту это противоположные
стороны улицы в нескольких километрах друг от друга. Между репликой с адресом и записью адреса
в карточку три реплики оператора, и ни одна не возвращается к адресу — это и есть нарушение
порядка работы, которое экран разбора показывает из данных.

## Связанные SSE-события

Нет: обе ручки описывают завершённую попытку и после завершения не меняются.

## Кэшируемость

Класс «снимок попытки»: `staleTime` `Infinity`, `gcTime` 30 мин, `retry` выключен. Данные
неизменяемы, перезапрашивать их по времени незачем.

## Открытые вопросы

1. Что считать нулём оси, если оператор ответил на звонок не сразу: момент поступления
   звонка или момент ответа? Предпочтение фронта — момент ответа (`answered_at` в
   `training_call`): до него оператор не мог ничего сказать, и задержку ответа удобнее показывать
   отдельной величиной, а не сдвигом всех реплик.
2. Отдавать ли в таймлайне действия, совершённые после отбоя, — например, `DECISION` на 151 с при
   звонке длиной 98 с. Предпочтение фронта — да, ось продолжается после звонка: обработка карточки
   на отбое не заканчивается.
3. Нужен ли в `FIELD_SET` человекочитаемый `label` поля или фронт переводит `path` сам.
   Предпочтение фронта — переводит сам по словарю, как уже делает для `discrepancies[].path`.

## Требуется на бэкенде

| Приоритет | Что реализовать | Блокирует |
|---|---|---|
| P1 | `GET /training-sessions/{id}/call-transcript` | расшифровка звонка на экране разбора; фронт на моке |
| P1 | `GET /training-sessions/{id}/timeline` с общей осью `utterances_offset_base` | сопоставление речи и действий, разбор порядка работы; фронт на моке |
| P2 | Ссылка из `FIELD_SET` на `action_id` в `training_action` | переход от события таймлайна к записи в журнале действий |

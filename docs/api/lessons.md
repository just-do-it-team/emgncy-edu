# Занятия

Статус: реализовано на существующих ручках, дельты — в «Требуется на бэкенде»
Потребитель на фронте: `features/teacher-lessons`, `features/assign-lesson`; экраны «Обзор», «Занятия»,
«Назначить занятие», «Результаты занятия»
Связанные файлы фронта: `frontend/src/features/teacher-lessons/**`, `frontend/src/features/assign-lesson/**`,
`frontend/src/entities/{assignment,group,monitoring}/**`,
`frontend/src/pages/{teacher-overview,teacher-lessons,teacher-lesson-assign,teacher-lesson-results}/**`,
`frontend/src/widgets/teacher-attempts-table/**`

## Назначение

Отдельной сущности «занятие» на бэкенде нет и не будет: занятие — это назначенный сценарий.
Назначения одной группе, созданные одним запросом `POST /learning-groups/{id}/scenario-assignments`,
объединены пакетом (`assignment_batch_id`, задаёт сервер); пакет и считается занятием. Назначение без пакета — занятие из одного
назначения. Ручки чтения пакета нет, фронт собирает занятие на клиенте.

Ранее описанные здесь `GET /api/v1/lessons`, `GET /api/v1/lessons/{id}`,
`GET /api/v1/lessons/{id}/summary` и `GET /api/v1/lessons/{id}/results` сняты: их не будет.
Выдуманный слой фронта на них удалён.

## Ручки

### GET /api/v1/scenario-assignments
Назначение: назначения преподавателя.
Отношение к существующему: существующая (`backend/src/s112/api/common/training/assignments.py:16`).
Query: `assigned_by` — преподаватель; `group_id` — назначения пакетов этой группы.
Ответ: голый массив `ScenarioAssignmentResponse`: `id`, `scenario_id`, `scenario_name`,
`assignment_batch_id`, `status` (`ASSIGNED`, `RUNNING`, `COMPLETED`, `CANCELLED`, `EXPIRED`),
`available_from`, `due_at`, `created_at`, `participants[]`. Поля `group_id` в ответе нет.
Доступ: **проверки нет**.

### POST /api/v1/learning-groups/{group_id}/scenario-assignments
Назначение: назначить сценарий группе или выбранным обучаемым группы — создать занятие.
Отношение к существующему: существующая (`backend/src/s112/api/teacher/learners/api.py:262`,
`simulation_service.py` `create_group_assignment`). Фронт использует только её: она создаёт пакет.
Доступ: `TEACHER` — владелец группы, `ADMINISTRATOR` — любая группа. Чужая группа — 422
`Teacher does not own this learning group` (не 403). При включённой авторизации `assigned_by` обязан
совпасть с токеном, иначе 403.

Тело:
| Поле | Тип | Обязательно | По умолчанию на сервере | Описание |
|---|---|---|---|---|
| `scenario_id` | uuid | да | — | только `PUBLISHED` |
| `assigned_by` | uuid | да | — | преподаватель |
| `participant_ids` | uuid[] 1..100 | нет | все активные участники группы | подмножество группы |
| `participant_positions` | `{user_id: код службы \| null}` | при `participant_ids` — ровно на каждого | `{}` | `null` — оператор 112, код — позиция ДДС |
| `incoming_call_operators` | `{call_key: user_id}` | нет | `{}` | только для `SHARED`; обязателен, если операторов больше одного |
| `launch_policy` | enum | нет | `STUDENT_SELF_START` | `INDIVIDUAL` — только `STUDENT_SELF_START`, `SHARED` — только `TEACHER_START` |
| `max_attempts` | int 1..100 | нет | 1 | |
| `available_from` | datetime | нет | `null` — без ограничения | до этого момента старт отклоняется 409 |
| `due_at` | datetime | нет | `null` — без срока | должен быть позже `available_from`; после него старт отклоняется 409 |

Что делает сервер:
- `INDIVIDUAL` — по назначению на каждого участника, все в одном пакете;
- `SHARED` — одно назначение на всех; число участников — в `min_participants..max_participants`;
- снимок сценария и шаблонов пишется в назначение; деактивированный шаблон — 422;
- повторное назначение того же сценария тем же обучаемым и пересечение сроков **не проверяются**.

Роли участника:
- на входящий звонок работает только участник с `position_code = null`; сценарий со звонками без
  оператора — 422;
- действия ДДС по карточке доступны только участнику с позицией, и только по карточкам, пришедшим в
  его службу. Индивидуальный сценарий ДДС без позиции назначить можно, но обучаемый не сможет
  принять ни одной карточки;
- индивидуальный сценарий со звонками и карточками одним участником полностью не выполняется:
  оператор 112 не работает за ДДС.

Успешный ответ: 201, `AssignmentBatchResponse`: `id` (это id занятия на фронте), `group_id`,
`scenario_id`, `participant_ids`, `assignments[]`.

Ошибки (строка в `detail`, 422 из `ValidationError`):
| Код | Когда |
|---|---|
| 404 | группы или сценария нет |
| 409 | группа в архиве |
| 422 | сценарий не утверждён; участник вне активного состава группы; позиции не на каждого участника; одна позиция ДДС у двух участников **в пакете**; число участников вне диапазона; неверная политика запуска; звонки без оператора; звонок не закреплён при нескольких операторах; неизвестная служба позиции; шаблон деактивирован; `due_at <= available_from`; чужая группа |

**Ограничение, которое обходит фронт.** Проверка «одна позиция ДДС — один участник» стоит в схеме
запроса и не знает режима сценария. Индивидуальный сценарий ДДС нельзя назначить группе одним
пакетом, если у двух обучаемых одна служба, хотя рабочие места у них разные. Фронт раскладывает
диспетчеров по пакетам так, чтобы службы в пакете не повторялись: разные службы — одно занятие,
повтор службы — следующее. Дельта — «Требуется на бэкенде».

Как фронт строит запросы (`features/assign-lesson/model/assignment-plan.ts`):
| Случай | Запросы |
|---|---|
| одно задание, индивидуальный сценарий со звонками | один пакет на группу |
| одно задание, индивидуальный сценарий ДДС | пакеты без повтора службы внутри: у всех разные службы — один пакет, одна служба у N обучаемых — N пакетов |
| одно задание, общее рабочее место | один пакет; все участники из одной группы, иначе фронт не отправляет |
| разные задания | пакет на пару «группа — сценарий», по тем же правилам |

Запросы идут последовательно; при частичном успехе показываются созданные занятия со ссылками,
несозданные с причиной и кнопка «Повторить неудавшиеся». Двойная отправка заблокирована на время
запросов, форма после отправки не отправляется повторно.

### POST /api/v1/scenario-assignments
Назначение без пакета, тело `ScenarioAssignmentCreate` — те же поля без группы, `participant_ids`
обязательны. Фронт не использует: занятие без группы не получает названия группы.

### GET /api/v1/learning-groups
Назначение: группы преподавателя с составом. Query: `teacher_id`, `active_only`.

### GET /api/v1/teacher-monitoring/sessions
Назначение: сессии преподавателя. Query: `teacher_id`; `status` — по умолчанию `RUNNING`,
пустое значение отдаёт все статусы.
Ответ: `session_id`, `assignment_id`, `assignment_batch_id`, `group_name`, `scenario_name`,
`status`, `started_at`, `completed_at`, `score` (строка-десятичное), `passed`,
`participants[]` с `display_name` и `participant_role`.

## Как фронт собирает занятие

1. `scenario-assignments?assigned_by=` — все назначения преподавателя.
2. `learning-groups?teacher_id=`, затем `scenario-assignments?assigned_by=&group_id=` на каждую
   группу — так пакет получает название группы (N+1 запрос).
3. Назначения группируются по `assignment_batch_id`, без пакета — по `id`.
4. Состояние занятия сводится из статусов назначений: все `CANCELLED` — отменено; есть
   `RUNNING` — идёт; все из `COMPLETED`, `EXPIRED`, `CANCELLED` — завершено; иначе
   запланировано.
5. Попытки занятия — завершённые сессии монитора, чей `assignment_id` входит в занятие.
6. Средний балл и доля зачётов считаются на клиенте по уже выставленным сервером `score` и
   `passed` и подписываются «среднее по N показанным попыткам». Балл попытки не
   пересчитывается. Нет оценённых попыток — «нет данных», а не ноль.

Нормативы (30 с подтверждения, 180 с обработки) фиксированы, берутся из
`shared/config/time-norms.ts`.

Страница занятия дополнительно показывает из `ScenarioAssignmentResponse` политику запуска
`launch_policy`, число попыток `max_attempts`, ревизию `scenario_revision` и участников
`participants[]` (роль, позиция ДДС, статус, `ready_at`, `completed_at`). Попытки участника
считаются так же, как на сервере: число сессий назначения из монитора против `max_attempts`.
Сценарий занятия читается из `GET /training-scenarios/{id}` — это текущая ревизия, а не
снимок назначения: при расхождении `revision` и `scenario_revision` страница предупреждает.

Отчёт по занятию формируется на клиенте в PDF из тех же данных: сводка занятия, разборы
завершённых попыток и таблица попыток.

## Кэшируемость

Назначения и группы — полусправочники: 5 мин / 30 мин. Сессии монитора — список: 30 с / 5 мин.
После назначения инвалидируется `assignmentKeys.all`: обновляются «Занятия», «Обзор» и блок
«Используется в занятиях» в карточке сценария — все строятся из списка назначений.

## Требуется на бэкенде

| Приоритет | Что реализовать | Что сейчас в интерфейсе |
|---|---|---|
| P0 | Проверка доступа в `GET /scenario-assignments` | назначения любого преподавателя читаются по его id |
| P1 | `group_id` и `group_name` в `ScenarioAssignmentResponse` или ручка чтения пакета | группа пакета ищется N+1 запросом |
| P1 | Сводка занятия: средний балл, доля зачётов, разбивка по критериям и классам ошибок | среднее и доля считаются на клиенте, критериев и классов ошибок в сводке нет |
| P1 | Проверку «одна позиция ДДС — один участник» в групповом назначении делать только для `SHARED` | индивидуальный сценарий ДДС группе с одной службой раздаётся отдельными занятиями, созданными не атомарно |
| P1 | Проверка повторного назначения: предупреждение или 409, если у обучаемого уже есть активное назначение того же сценария | фронт показывает отметку «уже есть активное занятие» только по своим назначениям |
| P1 | Индивидуальный сценарий ДДС без позиции — 422 при назначении | фронт требует выбрать службу, сервер пропускает |
| P2 | Пакет с разными сценариями или на обучаемых из разных групп | «разные задания» создают несколько занятий, по одному на пару «группа — сценарий» |
| P2 | Индивидуальный смешанный сценарий (звонки и карточки): роль «оператор 112 + ДДС» у одного участника | фронт предупреждает, что карточки ДДС останутся без обработки |
| P2 | `scenario_snapshot` назначения в ответе (или ручка чтения снимка) | состав на странице занятия берётся из текущей ревизии сценария; при другой ревизии показано предупреждение |

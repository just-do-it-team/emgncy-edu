# Занятия и результаты занятия

Статус: черновик

**Уточнение модели:** в проекте «занятие» — это `training_scenario`, а его
назначение группе — `assignment_batch`. Отдельный агрегат `lesson`, вложенный
набор сценариев и маршруты `/lessons` из черновика ниже не являются согласованным
контрактом. Полезные требования к сводке, результатам и отчёту нужно перенести
на сценарий и конкретное назначение группе. Нормативы фиксированы и не
настраиваются преподавателем.
Потребитель на фронте: `entities/lesson`; экраны «Занятия», «Результаты занятия», «Обзор»
Связанные файлы фронта: `frontend/src/entities/lesson/*`, `frontend/src/pages/teacher-lessons/*`, `frontend/src/pages/teacher-lesson-results/*`

## Назначение

Занятие — единица работы преподавателя: группа, набор сценариев, нормативы, веса критериев,
режим, старт и завершение. На нём стоят три экрана: список занятий, результаты занятия и монитор.

На бэкенде сущности нет. Ближайшее — `scenario-assignments`: назначение связывает один сценарий
с участниками. Занятие уровнем выше: несколько сценариев, одна группа, общие нормативы, единый
отчёт. Натянуть отчёт о практическом занятии на назначение не получается — у назначения нет ни
группы, ни набора сценариев, ни состояния «идёт / завершено» на уровне занятия.

## Занятие — снимок нормативов на момент проведения

Нормативы и веса критериев занятие хранит снимком, как и попытка
(правила проекта по оформлению контрактов, `docs/api/attempts.md`). Преподаватель меняет
нормативы между занятиями; отчёт двухнедельной давности обязан показывать те, по которым
занятие проводилось.

## Ручки

### GET /api/v1/lessons

Назначение: список занятий преподавателя.
Отношение к существующему: **новая**. Ближайшее — `GET /api/v1/scenario-assignments`, но оно не
знает ни занятия, ни группы, ни агрегированного балла.
Доступ: `TEACHER` — свои занятия; `ADMINISTRATOR` — все; `STUDENT` — 403.

Query:

| Имя | Тип | Обязателен | По умолчанию | Описание |
|---|---|---|---|---|
| `status` | enum | нет | — | `PLANNED`, `RUNNING`, `FINISHED`, `CANCELLED` |
| `group_id` | uuid | нет | — | фильтр по группе |
| `cursor` | string | нет | — | курсор следующей страницы |
| `limit` | int | нет | 100 | 1..500 |

Успешный ответ: 200, голый массив:

| Поле | Тип | Описание |
|---|---|---|
| `lesson_id` | uuid | идентификатор |
| `name` | str | название занятия |
| `group_name` | str | группа, снимок названия |
| `scenarios_count` | int | сколько сценариев в занятии |
| `attempts_total` | int | завершённых попыток |
| `average_total` | number \| null | средний балл, `null` пока попыток нет |
| `status` | enum | состояние занятия |
| `started_at` | datetime | время проведения |
| `assigned_at` | datetime \| null | когда занятие назначено группе |
| `due_at` | datetime \| null | срок прохождения; `null` — без срока |
| `attempts_allowed` | int \| null | сколько попыток разрешено каждому; `null` — без ограничения |

### GET /api/v1/lessons/{lesson_id}

Назначение: занятие целиком для шапки экрана результатов.
Доступ: как выше.

Успешный ответ: 200

| Поле | Тип | Описание |
|---|---|---|
| `lesson_id` | uuid | идентификатор |
| `name` | str | название |
| `group_id`, `group_name` | uuid, str | группа и снимок её названия |
| `scenarios` | array | `[{scenario_id, name, difficulty}]` — снимок состава |
| `norms` | object | `{ack_seconds, fill_seconds}` — снимок нормативов |
| `started_at` | datetime | старт |
| `finished_at` | datetime \| null | завершение |
| `status` | enum | состояние |
| `participants_count` | int | участников |
| `assigned_at` | datetime \| null | когда занятие назначено группе |
| `due_at` | datetime \| null | срок прохождения; `null` — без срока |
| `attempts_allowed` | int \| null | сколько попыток разрешено каждому; `null` — без ограничения |

Ошибки: 404 — занятия нет; 403 — чужое занятие.

Пример ответа:

  "group_id": "7c1e5a93-4d86-4f27-9b35-8e2a6c4f1d90",
  "group_name": "УМЦ-112, группа 4",
  "scenarios": [
    { "scenario_id": "e2a9c541-7b38-4d95-8f16-3c7e1a5d9b40", "name": "Задымление мусоропровода в жилом доме", "difficulty": 2 }
  ],

  "started_at": "2026-09-15T10:00:00+03:00",

### Три проекции результатов занятия

Ниже три ручки об одном и том же занятии. Это не повтор одной просьбы, у каждой свой разрез:

| Ручка | Разрез | Для чего |
|---|---|---|
| `GET /lessons/{lesson_id}/summary` | по занятию целиком, одна запись | средний балл, критерии, счётчики ошибок над таблицей |
| `GET /lessons/{lesson_id}/attempts` | по попыткам, строка на попытку | таблица попыток с переходом в разбор каждой |
| `GET /lessons/{lesson_id}/results` | по людям, строка на обучающегося | кто сколько попыток использовал, лучший балл, зачтено ли |

Разрез «по людям» нельзя собрать из двух других на клиенте: `attempts` не содержит тех, кто
ещё не начинал, а `summary` не знает, кто какой балл получил.

### GET /api/v1/lessons/{lesson_id}/summary

Назначение: агрегированная сводка занятия для блока над таблицей попыток.
Отношение к существующему: **новая**. Считать её на клиенте нельзя: `docs/domain/ekp.md` требует, чтобы
балл и критерии приходили с бэкенда, а клиент их только отображал.
Доступ: `TEACHER`, `ADMINISTRATOR`.

Успешный ответ: 200

| Поле | Тип | Описание |
|---|---|---|
| `lesson_id` | uuid | занятие |
| `attempts_total` | int | завершённых попыток |
| `attempts_passed` | int | из них с зачётом |
| `average_total` | number | средний итоговый балл |
| `criteria` | object | ключи `C1`..`C7`, каждый `{weight, value, points}` — средние по занятию, веса из снимка |
| `error_counts` | object | `{critical, significant, minor}` — суммарно по занятию |

Ошибки: 409 — занятие не завершено, сводка ещё не собрана; 404; 403.

### GET /api/v1/lessons/{lesson_id}/attempts

Назначение: попытки занятия для таблицы.
Отношение к существующему: **это ручка из `docs/api/attempts.md`**, здесь она только упоминается.
Формат ответа — `AttemptSummary`, описан там же.

### GET /api/v1/lessons/{lesson_id}/results

Назначение: результаты занятия по каждому обучающемуся группы.
Отношение к существующему: **новая**.
Доступ: `TEACHER` — своё занятие; `ADMINISTRATOR` — любое; `STUDENT` — 403.

Успешный ответ: 200, голый массив, **по записи на каждого участника группы**, включая тех,
кто не сделал ни одной попытки.

| Поле | Тип | Описание |
|---|---|---|
| `student_id` | uuid | обучающийся; имя берётся из состава группы |
| `attempts_used` | int | сколько попыток использовано, от 0 до `attempts_allowed` |
| `best_score` | string \| null | лучший итоговый балл, Decimal строкой, как `final_score` в `/student/training-history`; `null` — попыток нет |
| `last_attempt_id` | uuid \| null | последняя попытка, для перехода в разбор; `null` — попыток нет |
| `passed` | bool \| null | зачтено ли по лучшей попытке; `null` — попыток нет |

Инварианты: `best_score`, `last_attempt_id` и `passed` равны `null` тогда и только тогда,
когда `attempts_used = 0`. Сумма `attempts_used` по всем записям равна `attempts_total`
из `GET /lessons`.

Пример ответа:

```json
[
  {
    "student_id": "00000000-0000-0000-0000-000000000202",
    "attempts_used": 2,
    "best_score": "86.00",
    "last_attempt_id": "2c5e7a9b-1d3f-4b68-8e4a-6f8b0d2c4e71",
    "passed": true
  },
  {
    "student_id": "b02d4f68-3e5a-4c79-9b1f-0a2c4e6d8f37",
    "attempts_used": 0,
    "best_score": null,
    "last_attempt_id": null,
    "passed": null
  }
]
```

Ошибки: 404 — занятия нет; 403 — чужое занятие.
Кэшируемость: класс «списки», `staleTime` 30 с; инвалидация по `attempt.scored` и
`session.finished`.

### POST /api/v1/lessons/{lesson_id}/report

Назначение: экспорт отчёта о практическом занятии.
Отношение к существующему: **новая**. Ближайшее — `GET /api/v1/admin/reports/user-actions/export`,
но это аудит действий, а не отчёт о занятии.
Доступ: `TEACHER` — своё занятие; `ADMINISTRATOR`.

Тело запроса:

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `format` | enum | да | `XLSX`, `PDF` | формат выгрузки |
| `include_attempts` | bool | нет | — | включать поимённую таблицу попыток, по умолчанию `true` |
| `request_id` | string | нет | ≤128 | дедупликация |

Успешный ответ: 200, файл. Ошибки: 409 — занятие не завершено; 403; 422.

До реализации кнопка «Экспорт отчёта» на экране результатов заблокирована с тултипом,
объясняющим причину: `docs/domain/roles.md` требует явной блокировки с пояснением, а не скрытия.

## Связанные SSE-события

| Событие | Когда | Полезная нагрузка | Что делает фронт |
|---|---|---|---|
| `session.started` | занятие переведено в `RUNNING` | `lesson_id` | `setQueryData` на элемент списка занятий |
| `session.finished` | занятие завершено | `lesson_id` | инвалидация занятия, его сводки и списка попыток |
| `attempt.scored` | собран снимок попытки | `lesson_id`, `attempt_id` | инвалидация сводки занятия, `setQueryData` на строку попытки |

Событий занятия на бэкенде нет, они в списке требований в правилах проекта по контракту
бэкенда.

## Кэшируемость

| Данные | Класс | `staleTime` | Инвалидация |
|---|---|---|---|
| Список занятий | списки | 30 с | `session.started`, `session.finished` |
| Занятие | полусправочники | 5 мин | правка занятия, `session.finished` |
| Сводка занятия | полусправочники | 5 мин | `attempt.scored`, экспертная правка оценки, `session.finished` |

Ключи — фабрика `lessonKeys` (`entities/lesson/api/lesson.keys.ts`), по конвенции из
правил кэширования проекта.

## Открытые вопросы

1. **Занятие и назначение.** Занятие порождает назначения на каждый свой сценарий или заменяет их
   целиком? Предпочтение фронта — порождает: назначение остаётся единицей выдачи сценария
   участнику, занятие становится их родителем.
2. **Смешанные режимы.** ТЗ допускает смешанный набор сценариев, то есть в одном занятии могут
   быть и АРМ-112, и АРМ ДДС. Сводка тогда усредняет критерий `C7` по попыткам, где он применим.
   Нужно подтвердить, что `C7` для `ARM112` приходит как «неприменимо», а не как ноль.
3. **Веса критериев.** Задаются на уровне занятия или наследуются от сценария? Предпочтение
   фронта — занятие: преподаватель настраивает их перед проведением, а снимок кладётся в попытку.

## Требуется на бэкенде

| Приоритет | Что реализовать | Блокирует |
|---|---|---|
| P0 | Агрегат «занятие»: группа, набор сценариев, нормативы, веса, состояние, старт и завершение | все три экрана преподавателя; сейчас фронт живёт на моках `entities/lesson` |
| P0 | `GET /api/v1/lessons`, `GET /api/v1/lessons/{id}`, включая `assigned_at`, `due_at`, `attempts_allowed` | список занятий и шапка результатов; фронт на моке `lesson-contract.mocks.ts` |
| P0 | `GET /api/v1/lessons/{id}/summary` со средними по `C1`..`C7` и счётчиками ошибок | сводка занятия; считать на клиенте запрещено `docs/domain/ekp.md` |
| P1 | `GET /api/v1/lessons/{id}/attempts` — та же проекция `AttemptSummary`, что в `attempts.md`, но с фильтром по занятию | таблица попыток на экране результатов |
| P1 | `GET /api/v1/lessons/{id}/results` — строка на каждого участника группы, включая не начинавших | таблица результатов по людям; фронт на моке `lesson-contract.mocks.ts` |
| P1 | `POST /api/v1/lessons/{id}/report` | экспорт отчёта о практическом занятии, требование ТЗ |
| P1 | События `session.started`, `session.finished`, `attempt.scored` с `lesson_id` | список и сводка обновляются по факту, а не по таймеру |
| P2 | Фильтры списка по группе и состоянию, курсорная пагинация | при десятках занятий список нелистаемый |

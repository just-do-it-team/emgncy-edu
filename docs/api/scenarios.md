# Сценарии тренажёра

Статус: черновик
Потребитель на фронте: `entities/scenario`; экраны «Сценарии» и «Карточка сценария»
Связанные файлы фронта: `frontend/src/entities/scenario/*`, `frontend/src/pages/teacher-scenarios/*`, `frontend/src/pages/teacher-scenario-card/*`

## Назначение

Сценарий — заготовка вызова: признаки ЕКП, выведенный из них итоговый тип, главная служба,
список оповещения, норматив обработки и вес в оценке. Из сценариев собирается занятие, а его
эталонная карточка попадает снимком в попытку.

На бэкенде частично есть: `GET POST /api/v1/training-scenarios`, `GET PATCH
/api/v1/training-scenarios/{id}` с полями `name`, `description`, `difficulty`,
`estimated_duration_seconds`, `cards_count`, `workspace_mode`, `definition`, `revision`,
`status`. Недостаёт того, ради чего преподаватель открывает список: итогового типа по ЕКП,
главной службы, списка оповещения, веса в оценке и числа проведённых занятий.

## Ручки

### GET /api/v1/training-scenarios

Назначение: список сценариев для таблицы раздела.
Отношение к существующему: **дельта** — ручка есть, ответу недостаёт полей.
Доступ: `TEACHER`, `ADMINISTRATOR`. `STUDENT` — 403: состав сценария раскрывает эталон.

Query: `status`, `difficulty` (есть), плюс `cursor` и `limit` — дельта.

Успешный ответ: 200, голый массив. Существующие поля плюс:

| Поле | Тип | Дельта | Описание |
|---|---|---|---|
| `incident_type_name` | str | **новое** | итоговый тип по ЕКП, как в классификаторе: «пожар: балкон» |
| `weight` | number | **новое** | вес сценария в оценке занятия |
| `fill_norm_seconds` | int | **новое** | норматив обработки; сейчас есть `estimated_duration_seconds`, это другое |
| `used_in_lessons` | int | **новое** | в скольких занятиях использован |

### GET /api/v1/training-scenarios/{scenario_id}

Назначение: карточка сценария.
Отношение к существующему: **дельта** к существующей ручке.
Доступ: как выше.

Успешный ответ: 200. Существующие поля плюс:

| Поле | Тип | Описание |
|---|---|---|
| `mode` | `ARM112` \| `DDS` | режим рабочего места; открытый вопрос 2 в `attempts.md` |
| `incident_type_name`, `ekp35_incident_type` | str | итоговый тип и тип ЕКП-35 |
| `features` | array | `[{level, group, feature_id, code, name}]` — цепочка признаков с вопросами опросной карты |
| `main_service` | object | `{service_id, name, is_main: true}` — главная служба, выведенная из ЕКП |
| `notification_list` | array | `[{service_id, name, is_main}]` — список оповещения целиком |
| `weight`, `fill_norm_seconds`, `used_in_lessons` | number | как в списке |

## Связанные SSE-события

Нет. Сценарий меняется правкой преподавателя, экран обновляется инвалидацией после мутации.

## Кэшируемость

| Данные | Класс | `staleTime` | Инвалидация |
|---|---|---|---|
| Список сценариев | полусправочники | 5 мин | после `PATCH` сценария |
| Карточка сценария | полусправочники | 5 мин | после `PATCH` этого сценария |

Ключи — фабрика `scenarioKeys` (`entities/scenario/api/scenario.keys.ts`).

## Открытые вопросы

1. **Вес сценария.** Вес в оценке принадлежит сценарию или занятию? В `lessons.md` открытый
   вопрос 3 предлагает занятие. Если так, `weight` в ответе сценария — значение по умолчанию,
   которое занятие может переопределить; это нужно назвать в схеме явно.
2. **Норматив.** `estimated_duration_seconds` уже есть, но это оценка длительности, а не норматив
   обработки карточки. Вводим отдельное поле `fill_norm_seconds` или переосмысливаем существующее?
   Предпочтение фронта — отдельное: у них разный смысл и разные последствия для оценки.
3. **Доступ обучающегося.** Сейчас предполагается 403. Если раздел «Материалы» будет отдавать
   обучающемуся разбор сценария после занятия, понадобится урезанная проекция без эталона.

## Требуется на бэкенде

| Приоритет | Что реализовать | Блокирует |
|---|---|---|
| P0 | `incident_type_name`, `main_service`, `notification_list`, `features` с вопросами опросной карты в ответе сценария | карточка сценария; сейчас преподаватель не видит, что именно проверяет сценарий |
| P1 | `weight` и `fill_norm_seconds` в списке и карточке | колонки «вес» и «норматив», расчёт оценки занятия |
| P1 | `used_in_lessons` | колонка «использован раз»; иначе непонятно, какие сценарии живые |
| P1 | `mode` (`ARM112`/`DDS`) как поле сценария | режим попытки, открытый вопрос 2 в `attempts.md` |
| P2 | Курсорная пагинация списка сценариев | при сотне сценариев список нелистаемый |

# Попытки обучающегося: разбор, результаты занятия

Статус: черновик
Потребитель на фронте: `entities/attempt`; экраны разбора попытки, результатов занятия, монитора
Связанные файлы фронта: `frontend/src/entities/attempt/model/*`, `frontend/src/entities/attempt/api/attempt-api.ts`, `frontend/src/entities/attempt/api/attempt-mocks.ts`

## Назначение

Попытка — единица разбора: что обучающийся сделал по одному сценарию, за какое время, с какими
ошибками и каким баллом. На ней стоят три экрана: разбор попытки преподавателем, результаты
занятия по группе, монитор занятия.

Сейчас на бэке есть `GET /api/v1/training-sessions/{id}` (`TrainingSessionResponse` с
`score`, `passed`, `result`) и `GET /api/v1/training-sessions/{id}/actions`
(`TrainingActionResponse`). Этого недостаточно: нет раскладки балла по критериям, нет списка
ошибок, нет эталонной карточки, нет привязки ошибки к моменту в таймлайне. Без них разбор
показывает «балл 76» вместо «вот здесь, на 24-й секунде, введена не та улица».

## Попытка — иммутабельный снимок

**Бэкенд обязан собрать снимок в момент завершения попытки и хранить его, а не собирать ответ
на лету при запросе.** Ничего в попытке не резолвится по ссылке в текущее состояние.

Снимком лежат:

| Что | Почему не ссылкой |
|---|---|
| `reference_card` целиком | сценарий отредактируют или перегенерируют после занятия, и старый разбор начнёт сравнивать ответ с чужим эталоном |
| `timings.*.norm_seconds` | преподаватель меняет нормативы между занятиями |
| `scenario.name`, `scenario.difficulty`, `scenario.revision` | название и сложность правят; `revision` позволяет проверить, какой версии соответствует снимок |
| `score.criteria[C].weight` | веса задаёт преподаватель; разбор обязан показывать веса, по которым попытку оценили, а не текущие |
| `student.full_name`, `student.workstation_number` | человека переводят в другую группу, номер рабочего места меняется |

По ссылке остаются только идентификаторы: `scenario_id`, `student_id`, `lesson_id`,
`assignment_id` — для перехода к текущей версии сценария или к профилю обучающегося.

Проверка корректности реализации: повторный запрос той же попытки через неделю, после правок
сценария и нормативов, обязан вернуть тот же результат до последнего поля.

## Ручки

### GET /api/v1/training-sessions/{training_session_id}/attempt

Назначение: попытка целиком для экрана разбора.
Отношение к существующему: **дельта к `GET /api/v1/training-sessions/{id}`** — новая проекция
на том же агрегате. Существующую ручку не меняем: она используется другими сценариями.
Доступ: `TEACHER` и `ADMINISTRATOR` — любая попытка своего занятия; `STUDENT` — только свои
попытки. Чужие попытки обучающемуся недоступны (403).

Параметры пути:

| Имя | Тип | Описание |
|---|---|---|
| `training_session_id` | uuid | сессия тренажёра, она же попытка |

Успешный ответ: 200

| Поле | Тип | Описание |
|---|---|---|
| `attempt_id` | uuid | совпадает с `training_session_id` |
| `lesson_id` | uuid | занятие, см. открытый вопрос 1 |
| `assignment_id` | uuid | из `TrainingSessionResponse.assignment_id` |
| `attempt_number` | int | из `TrainingSessionResponse.attempt_number` |
| `incident_card_number` | str | номер карточки, как в шапке ПОВ-112 («36814862»); из `CardResponse.card_number` |
| `mode` | `ARM112` \| `DDS` | режим рабочего места, см. открытый вопрос 2 |
| `student` | object | `student_id`, `full_name`, `workstation_number` — снимок |
| `scenario` | object | `scenario_id`, `revision`, `name`, `difficulty`, `reference_incident_type` — снимок |
| `questionnaire` | array | опросная карта целиком: `[{group, options: [{feature_id, code, name}]}]` — снимок |
| `started_at`, `completed_at` | datetime | из `TrainingSessionResponse` |
| `timings` | object | `ARM112`: только `fill`; `DDS`: `ack` и `fill`. Каждый — `{actual_seconds, norm_seconds}` |
| `score` | object | `criteria` (ключи `C1`..`C7`, каждый `{weight, value, points}`), `total`, `passed` |
| `submitted_card` | object | карточка обучающегося, см. «Карточка» |
| `reference_card` | object | эталонная карточка, тот же тип |
| `errors` | array | список ошибок, см. «Ошибки» |
| `actions` | array | таймлайн, см. «Действия» |
| `expert_review` | object \| null | экспертная правка преподавателя |

Ошибки:

| Код | Когда | Тело |
|---|---|---|
| 403 | обучающийся запрашивает чужую попытку | `{"detail": "Доступ к чужой попытке запрещён"}` |
| 404 | попытки нет | `{"detail": "Попытка не найдена"}` |
| 409 | попытка не завершена, снимка ещё нет | `{"detail": "Попытка не завершена"}` |

Пагинация: не применяется. Конкурентность: ответ иммутабелен, `expected_*` не нужен.

### GET /api/v1/lessons/{lesson_id}/attempts

Назначение: список попыток занятия для экрана результатов.
Отношение к существующему: **новая**. Ближайшее из существующего —
`GET /api/v1/training-sessions?assignment_id=&participant_user_id=&status=`, но оно отдаёт
`TrainingSessionResponse` без ФИО, номера АРМ, сложности и счётчиков ошибок, и не знает про
занятие. См. открытый вопрос 1.
Доступ: `TEACHER`, `ADMINISTRATOR`. `STUDENT` — 403: чужие результаты ему недоступны.

Query:

| Имя | Тип | Обязателен | По умолчанию | Описание |
|---|---|---|---|---|
| `cursor` | string | нет | — | курсор следующей страницы |
| `limit` | int | нет | 100 | 1..500 |
| `passed` | bool | нет | — | фильтр по зачёту |

Успешный ответ: 200, голый массив `AttemptSummary`:

| Поле | Тип | Описание |
|---|---|---|
| `attempt_id`, `lesson_id`, `assignment_id` | uuid | идентификаторы |
| `attempt_number` | int | номер попытки |
| `mode` | `ARM112` \| `DDS` | режим |
| `student` | object | `student_id`, `full_name`, `workstation_number` |
| `scenario` | object | `scenario_id`, `revision`, `name`, `difficulty` |
| `completed_at` | datetime | завершение |
| `timings` | object | `ack` (null для `ARM112`), `fill` |
| `total` | number | итоговый балл с учётом экспертной правки |
| `passed` | bool | зачёт |
| `error_counts` | object | `critical`, `significant`, `minor` |

**Это самостоятельная проекция, а не урезанная попытка.** Полные попытки списком не отдаются:
тридцать участников с двумя карточками и таймлайнами — мегабайты на один экран.

Сортировка по умолчанию: `completed_at` по возрастанию. Пагинация курсорная; ответ несёт
`next_cursor` заголовком `X-Next-Cursor` либо, если по проекту принят другой способ, любым
единым для всего API — см. дельту в правилах проекта по контракту бэкенда.

### POST /api/v1/training-sessions/{training_session_id}/attempt/review

Назначение: экспертная правка итогового балла преподавателем.
Отношение к существующему: **новая**. `PATCH /api/v1/training-scenarios/{id}` правит сценарий,
а не оценку.
Доступ: `TEACHER` — только попытки своего занятия; `ADMINISTRATOR` — запрещено во время
активного занятия (`docs/domain/roles.md`); `STUDENT` — 403.

Заголовки: `Idempotency-Key` не нужен, идемпотентность обеспечивает `expected_version`.

Тело запроса:

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `total` | number | да | 0..100 | новый итоговый балл |
| `comment` | string | **да** | 10..2000 | причина правки |
| `expected_version` | int | да | — | версия текущей правки, 0 если правки не было |
| `request_id` | string | нет | ≤128 | для дедупликации |

**Комментарий обязателен.** Правка без причины не принимается: 422. Это требование ТЗ по
аудиту, а не пожелание интерфейса — см. правила безопасности проекта.

Успешный ответ: 200 — попытка целиком, как у первой ручки, с заполненным `expert_review`:
`reviewed_by`, `reviewed_by_name`, `reviewed_at`, `previous_total`, `total`, `comment`.

Ошибки:

| Код | Когда | Тело |
|---|---|---|
| 403 | чужое занятие либо администратор во время активного занятия | `{"detail": "..."}` |
| 409 | конфликт версий | `{"detail": "Оценка изменена другим пользователем"}` |
| 422 | пустой или короткий комментарий | `{"detail": [{"loc": ["body", "comment"], "msg": "...", "type": "..."}]}` |

Правка обязана попасть в аудит (`GET /api/v1/admin/reports/user-actions`) с актором из токена,
а не из заголовков `X-Admin-Actor-*`.

## Карточка

Один тип для `submitted_card` и `reference_card`, дискриминатор — `mode`.

Общие поля: `source_type` (`SourceType` с бэка: `CALL`, `SMS`, `VIS`, `ERA_GLONASS`,
`REGIONAL_112`, `MANUAL`), `external_card_id`, `channel` (`{channel_id, name}` — оператор связи
или организация-источник, справочник), `phones` (`aon`, `provided`, `at_location`, `is_foreign`),
`applicant` (`full_name`, `status`), `address`, `event_type`, `event_kind`, `features`,
`final_incident_type`, `description`, `victims_count`, `services`.

`address`: `full`, `country`, `subject`, `settlement`, `object`, `okrug`, `district`, `street`,
`house`, `building`, `structure`, `apartment`, `entrance`, `floor`, `intercom_code`,
`descriptive`, `coordinates`. `okrug` — административный округ, `district` — район. Состав и
порядок полей повторяют адресную сетку реальной карточки ПОВ-112 (`СКРИНШОТ КАРТОЧКИ 112ГСИ`):
без `country`, `subject`, `settlement` и `object` экран разбора рисует пустые ячейки там, где
в системе стоят значения.

`services[]`: `service_id`, `name`, `is_main` (главная служба), `added_reason`
(`ServiceAddedReason` с бэка: `EKP`, `CLASSIFIER`, `MANUAL`, `VIS_UPDATE`).

`mode: "DDS"` добавляет `response_statuses[]`: `service_id`, `status` (`ServiceResponseStatus`
с бэка), `set_at`, `comment`.

**`comment` в статусе — `string | null` для всех статусов, включая `REJECTED` и `WORK_REFUSED`.**
Правило домена «эти статусы требуют комментария» проверяется при вводе и попадает в список
ошибок. Карточка ответа обязана уметь быть неправильной — иначе ошибку обучающегося негде
хранить.

## Ошибки

`errors[]`, дискриминатор — `kind`. Критерий и критичность определяются видом ошибки, а не
приходят произвольно.

| `kind` | `criterion` | `severity` | Дополнительно |
|---|---|---|---|
| `MAIN_SERVICE_MISSED` | C2 | CRITICAL | `service`, `ekp_feature` |
| `SERVICE_MISSED` | C2 | SIGNIFICANT | `service`, `ekp_feature` |
| `WRONG_INCIDENT_TYPE` | C1 | вычисляется | `ekp_feature` |
| `AMBIGUOUS_TOPONYM` | C4 | CRITICAL | — |
| `TOPONYM_TYPO` | C4 | вычисляется | — |
| `ADDRESS_MISMATCH` | C4 | вычисляется | `distance_meters` |
| `STATUS_WITHOUT_COMMENT` | C7 | CRITICAL | `service`, `status` |
| `STATUS_ORDER_VIOLATION` | C7 | вычисляется | `service`, `status`, `previous_status` |
| `NORM_EXCEEDED` | C5 | SIGNIFICANT | `stage` (`ACK`/`FILL`), `norm_seconds`, `actual_seconds` |
| `SPELLING` | C6 | MINOR | — |
| `REQUIRED_FIELD_EMPTY` | C3 | вычисляется | — |

Общие поля: `error_id`, `field`, `expected`, `actual`, `explanation`, `action_id`.

`explanation` пишется для преподавателя и объясняет последствие, а не констатирует факт:
не «неверная улица», а «расчёт выехал бы в Замоскворечье вместо Восточного Дегунина, около
20 километров и другой пожарный гарнизон».

`ekp_feature` — `{feature_id, feature_name, consequence}`, только у ошибок классификации:
«не выбран признак „Угроза жизни“ → не оповещена Служба 103».

**`action_id` обязателен везде, где момент определим.** Это главное в модели: разбор показывает
не балл, а момент, когда ошибка была совершена. `null` допустим только для ошибок-упущений,
у которых нет действия — например `REQUIRED_FIELD_EMPTY`.

Критичность берётся из `docs/domain/error-classes.md`. Отдельный случай неоднозначного
топонима показывается с обоими вариантами: `expected` и `actual` несут полные адреса с округом.

## Действия

`actions[]`, дискриминатор — `type`. Общие поля: `action_id`, `occurred_at`.

**Смещения от начала попытки в ответе нет и не нужно.** Клиент считает его из
`occurred_at − started_at`. Производное значение по сети не передаётся.

Соответствие типизированной нагрузки полям `TrainingActionResponse`:

| `type` | Нагрузка | Откуда на бэке |
|---|---|---|
| `CARD_OPENED` | `incident_card_id` | `incident_card_id` |
| `FIELD_CHANGED` | `field`, `previous_value`, `value` | `details.field`, `before_state`, `after_state` |
| `FEATURE_SELECTED` / `FEATURE_CLEARED` | `feature` | `after_state` / `before_state` |
| `ADDRESS_ENTERED` | `field`, `previous_value`, `value` | `before_state`, `after_state` |
| `SERVICE_ADDED` | `service`, `added_reason` | `after_state` |
| `SERVICE_REMOVED` | `service` | `before_state` |
| `STATUS_SET` | `service`, `status`, `previous_status`, `comment` | `before_state`, `after_state` |
| `CALL_STARTED` | `phone` | `details` |
| `CALL_ENDED` | — | — |
| `CARD_SAVED` | `incident_card_id` | `incident_card_id` |

`before_state` и `after_state` описывают эволюцию ответа во времени и для таймлайна годятся
полностью. Дифференциал «ответ против эталона» из них не строится: эталон не является ничьим
состоянием во времени. Эта ось считается из `submitted_card` против `reference_card`.

Фронт не принимает `before_state`/`after_state` как свободные объекты: нетипизированный
`object` на границе превращается в `any` на месте использования. Бэкенд раскладывает их по
полям выше.

| `session.finished` | занятие завершено | `lesson_id` | инвалидация списка попыток занятия |

сейчас их нет.

## Кэшируемость

| Данные | Класс по правилам кэширования проекта | `staleTime` | Инвалидация |
|---|---|---|---|
| Попытка целиком | карточка, но снимок иммутабелен | `Infinity` | только `attempt/review`; по времени не перезапрашивается |
| Список попыток занятия | списки | 30 с | `attempt.scored`, `session.finished`, экспертная правка |

Попытка — редкий случай, когда `staleTime: Infinity` обоснован: ответ не может измениться,
кроме как через экспертную правку, а она инвалидирует ключ явно.

## Открытые вопросы

1. **Закрыт.** Занятие — отдельный агрегат, контракт вынесен в `docs/api/lessons.md`. Путь второй
   ручки — `GET /api/v1/lessons/{lesson_id}/attempts`. Осталась связка «занятие и назначение»,
   она переформулирована открытым вопросом 1 в `lessons.md`.
2. **Режим рабочего места.** `ARM112` и `DDS` на бэке нет: в `WorkspaceMode` лежат `INDIVIDUAL`
   и `SHARED`, это про другое. Где хранить режим — в сценарии, в назначении или в рабочем
   пространстве? Предпочтение фронта — в сценарии: режим определяется содержанием задания.
3. **Справочник каналов связи.** Ручки нет. Нужен `GET /api/v1/channels` либо поле `channel`
   отдаётся развёрнутым в карточке без отдельного справочника. Предпочтение — справочник:
   в интерфейсе это выпадающий список с поиском.
4. **Статус заявителя.** Перечисления на бэке нет. Значения из `docs/domain/glossary.md`: очевидец,
   пострадавший, родственник, знакомый, ребёнок, участник. Фронт использует `WITNESS`, `VICTIM`,
   `RELATIVE`, `ACQUAINTANCE`, `CHILD`, `PARTICIPANT` — подтвердить или заменить.
5. **Тайминг подтверждения в `ARM112`.** Сейчас `ack` только в `DDS`, потому что `ACK_TIMEOUT` —
   это статус «Принята»/«Не принята» на стороне ДДС. Если для АРМ-112 нужен отдельный норматив,
   у него должен быть собственный смысл и собственное имя, а не переиспользованный `ack`.
6. **Экспертная правка — только итог или по критериям?** Сейчас правится `total`. Если нужна
   правка отдельных `C1`..`C7`, состав `expert_review` меняется, и это лучше решить до реализации.
7. **Кто считает `error_counts`** в сводке: бэкенд при сборке снимка или отдельный запрос.
   Предпочтение — бэкенд при сборке: счётчики являются частью снимка и не должны расходиться
   со списком ошибок.

# Приложение А. Глоссарий

Таблица 50 — Глоссарий

| Термин | Определение |
|---|---|
| Система-112 | Система приёма вызовов по единому номеру «112», регистрации и передачи информации в службы |
| ПОВ-112 | Информационная система системы-112 Москвы, интерфейс которой воспроизводит тренажёр |
| АРМ-112 | Автоматизированное рабочее место в двух режимах: оператор Службы 112 заводит карточку, диспетчер ДДС обрабатывает поступившую |
| ДДС | Дежурно-диспетчерская служба — получатель карточки, реагирует на происшествие |
| ЕКП | Единый классификатор происшествий: дерево признаков → итоговый тип → список оповещения |
| Опросная карта | Форма признаков происшествия, разворачивается после выбора типа; строится из ЕКП |
| Итоговый тип происшествия | Результат разрешения признаков 1–3 уровня по ЕКП; определяет список оповещения |
| Список оповещения | Набор служб, оповещаемых автоматически |
| Главная служба | Профильная служба типа; её пропуск — критическая ошибка |
| АОН | Автоматически определившийся номер заявителя |
| Описательный адрес | Адрес словами, когда точного нет: «напротив пруда», «во дворе» |
| Заявитель | Тот, кто звонит; в тренажёре — виртуальный собеседник |
| Обучаемый | Тот, кого тренируют |
| Позиция | Роль обучаемого в занятии: оператор 112 или диспетчер ДДС конкретной службы |
| Шаблон | Звонок 112 или карточка ДДС с эталоном; публикуется после проверки преподавателем |
| Эталон | Ожидаемое итоговое состояние карточки, статусы и доклад, с которыми сравниваются действия обучаемого |
| Сценарий | Набор шаблонов с условиями подачи, сложностью и порогом зачёта |
| Занятие | Назначение сценария группе или обучаемым с окном дат |
| Попытка | Одно прохождение занятия обучаемым |
| Норматив | Допустимое время: 30 с до раскрытия карточки, 3 мин до первой записи |
| STT, TTS | Распознавание речи и синтез речи |
| LLM | Большая языковая модель |
| SSE | Server-Sent Events — поток событий от сервера к браузеру |
| JWT | Токен доступа с ролью пользователя |
| Outbox | Таблица исходящих событий в БД, публикуемых в Kafka в той же транзакции, что и изменение данных |

# Приложение Б. Нормативные документы

1. Федеральный закон от 27.07.2006 № 149-ФЗ «Об информации, информационных технологиях и о защите информации» — требование ТЗ, разд. 13.
2. Федеральный закон от 27.07.2006 № 152-ФЗ «О персональных данных» — требование ТЗ, разд. 13; основание не хранить ПДн в браузере и URL и зафиксировать права на голосовые образцы.
3. Постановление Правительства РФ № 1931 — источник норматива 30 с до открытия карточки.
4. ГОСТ 19.505-79 «Руководство оператора. Требования к содержанию и оформлению» — структура раздела 10.

Материалы заказчика, на которые опирается предметная логика, — памятка «Работа на АРМ-112. Памятка для дежурно-диспетчерских служб» и классификатор происшествий — нормативными актами не являются и перечислены в разделе 5.9.

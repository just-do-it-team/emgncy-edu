# 4. Методы обработки данных

## 4.1. Распознавание речи

- Модель: **GigaAM-v3 e2e RNNT** (SberDevices), загружается локально из каталога моделей, без
  обращения в сеть.
- Вход: реплика из браузера (webm, ogg или mp4), до 25 МиБ. Длинные записи режутся на фрагменты
  не длиннее 18 с. На GPU кодировщик работает в fp16.
- Выход: текст реплики с длительностью. Он сохраняется как действие попытки и отображается
  в расшифровке звонка при разборе.
- Речь в оценке не участвует: входящий звонок оценивается по итоговой карточке. Расшифровка
  нужна для диалога и разбора.

## 4.2. Синтез речи

- Модель: **Qwen3-TTS 12Hz 0.6B Base** в формате GGUF (квантизация Q8_0) с проектором F16.
  Работает через собственный C++-воркер на llama.cpp с CUDA.
- Голос клонируется по референсной записи из каталога `models/refs`. Шаблон звонка хранит
  идентификатор голоса; генератор шаблонов выбирает мужской или женский голос по полу заявителя.
- Текст режется на сегменты до 120 символов, между сегментами пауза 120 мс. Ответ заявителя
  синтезируется по фразам по мере генерации, поэтому первая фраза звучит, пока модель
  продолжает писать ответ.

## 4.3. Диалог с моделью

- Модель **gpt-oss-20b** на OpenAI-совместимом llama-server в локальной сети. Потоковый режим,
  низкое усилие рассуждения.
- Контекст: системный промпт роли заявителя, эталон карточки как «знания заявителя» (что задано
  в эталоне, заявитель знает и может сказать), первая реплика из шаблона, последние 12 сообщений.
- Диспетчер ДДС разговаривает с руководителем бригады тем же механизмом.
- Голосовой доклад диспетчера проверяется смыслово: модель сравнивает расшифровку с эталонным
  текстом и возвращает сходство 0–1, недостающие факты и противоречия. Доклад засчитывается при
  сходстве не ниже порога из эталона (по умолчанию 0,8). Ошибка модели фиксируется как
  «проверка не выполнена», а не как ошибка обучаемого.

## 4.4. Генерация шаблонов моделью и проверка преподавателем

1. Преподаватель выбирает основную службу (101–104) и, при необходимости, дополнительные.
2. Сервер подбирает тип происшествия из ЕКП по основной службе и адрес. Модель заполняет
   карточку по JSON-схеме (температура 0,2): описание, заявитель, адрес, пострадавшие, сложность.
3. Результат проверяется программно: адрес начинается с «г. Москва,», описание дословно содержит
   адрес, адрес со слов заявителя совпадает с местом происшествия, общие поля звонка 112 и карточек
   ДДС одной генерации совпадают.
4. Шаблоны сохраняются черновиками с разбивкой на секции. Преподаватель по каждой секции
   выбирает «подтвердить», «исправить в редакторе» или «отклонить». Сервер не публикует шаблон,
   пока все секции не подтверждены или не исправлены.
5. Только опубликованные шаблоны можно включать в сценарии.

## 4.5. Автоподбор служб по классификатору

- Классификатор ЕКП (1283 записи) хранится локально на сервере и во фронтенде. Выбор группы
  и определяющих признаков 1–3 уровня однозначно даёт итоговый тип происшествия.
- Список оповещения строится по маршрутам записи с учётом обстоятельств («Правонарушение»,
  «Пострадавшие», «Газификация», «Нет доступа»). Главная служба типа всегда входит в список
  и стоит первой: маршруты с обстоятельствами могут исключать ветки служб, а пропуск главной
  службы — критическая ошибка.
- Службу, не попавшую в список автоматически, оператор может добавить вручную.
- Сервер сверяет классификацию карточек и эталонов с тем же справочником.

## 4.6. Сравнение с эталоном

Эталон задаёт итоговое состояние карточки и, для ДДС, историю статусов и доклад. Каждое поле
эталона — одна проверка.

| Поле | Способ сравнения |
|---|---|
| Классификация (группа, признаки, итоговый тип, флаги маршрутизации) | Строго |
| Службы в списке оповещения | Как множество, без учёта порядка |
| ФИО заявителя | Без учёта регистра, пунктуации, лишних пробелов и различия «ё/е» |
| Адрес со слов заявителя и место происшествия | То же, плюс приведение сокращений: «улица → ул», «дом → д», «корпус → корп», «строение → стр», «квартира → кв», «пр-т → проспект», «б-р → бульвар», «переулок → пер», «шоссе → ш», «проезд → пр» |
| Телефоны, число пострадавших, статус карточки, статусы служб | Строго |
| История статусов службы | Длина и каждый переход; номер бригады не сравнивается |
| Описание, комментарии к статусам | Не оцениваются (хранятся для разбора) |
| Доклад руководителю бригады | Смысловое сравнение моделью (п. 4.3) |

Поле эталона можно исключить из проверки или потребовать пустое значение. Режим задаётся для
каждого поля в редакторе.

**Сборка адреса на АРМ.** Форма АРМ содержит структурированный адрес и описательный адрес.
Сопоставление с полями эталона сделано по эталонам заказчика:

- **адрес со слов заявителя** = «г. Москва» + улица, дом, корпус, строение, подъезд, квартира;
- **место происшествия** = тот же адрес + «Объект» + описательный адрес («контейнерная
  площадка», «во дворе»).

Страна, округ и район в адрес не добавляются: в эталонах их нет, и они давали бы ложное
расхождение.

## 4.7. Балл и зачёт

- Балл элемента (карточки или звонка) = число пройденных проверок / число проверок × 100.
- Балл попытки = среднее по всем выпущенным карточкам и завершённым входящим звонкам.
- Зачёт — если балл не ниже порога зачёта сценария (0–100, по умолчанию 100).
- В разборе балл раскрывается по пути: итог → критерий C1–C7 → поле → действие и момент
  в записи звонка.

## 4.8. Нормативы 30 с / 3 мин

Нормативы фиксированы по уточнению заказчика. Преподаватель их не меняет.

| Норматив | Значение | Как считается |
|---|---|---|
| Раскрытие карточки | 30 с | От появления карточки в службе до открытия диспетчером |
| Первая запись | 3 мин | От появления карточки до первой записи: статус вместе с непустым комментарием |

- **Сервер** выставляет сроки раскрытия (30 с) и решения (180 с от открытия карточки) и учитывает
  их в балле. Поздние действия разрешены, но засчитываются как нарушение.
- **Монитор преподавателя, отчёт занятия и «Мои результаты»** считают нормативы по журналу
  действий попытки одной общей функцией, строго в формулировке заказчика: от выпуска карточки,
  первая запись — только статус с текстом. Таймер переходит в предупреждение на 70 % норматива.
- Время заполнения карточки в отчёте: у карточки ДДС — от выпуска до первой записи (± к нормативу
  3 мин); у звонка 112 — от ответа до создания карточки (норматива нет).

## 4.9. Экспертная оценка и очередь проверки

- Преподаватель — конечный валидатор. Оценка преподавателя (балл, зачёт, комментарий) заменяет
  автоматическую во всех итогах, отчётах и у обучаемого. Изменение фиксируется в журнале попытки.
- Если оценка отличается от автоматической, причина обязательна.
- Очередь проверки: без оценки преподавателя — «На проверке»; оценка совпала с автоматической
  по баллу и зачёту — «Подтверждены»; отличается — «Исправлены». Прерванные попытки в очередь
  не попадают.
- «Верно — подтвердить» сохраняет оценку, равную автоматической. После сохранения предлагается
  следующая непроверенная попытка того же занятия.

## 4.10. Аналитика

Считается во фронтенде по уже загружаемым данным (попытки, назначения, сценарии, контекст
оценки каждой попытки) за выбранный период и группу. Все пороги — именованные константы.

| Показатель | Методика |
|---|---|
| Тепловая карта ошибок | Строки — обучаемые, столбцы — группы проверок разбора (классификация, службы, полнота, адрес, тайминг, статусы, доклад). Ячейка — доля попыток с ошибкой среди попыток, где проверка применима к роли. Ошибки только в оформлении не считаются |
| Тренд | Средний итоговый балл последних 3 попыток минус средний балл предыдущих |
| Соблюдение нормативов | Доля раскрытий за 30 с и первых записей за 3 мин по карточкам ДДС |
| Готовность | По последним 5 попыткам: «готов к самостоятельной работе» — балл ≥ 85, зачтено ≥ 80 %, нормативы ≥ 90 %; «уверенно, есть поправки» — балл ≥ 70, зачтено ≥ 50 %, нормативы ≥ 70 %; иначе «нужна практика». У оператора 112 нормативы не учитываются. Подсказка показывает фактические значения |
| Рекомендуемая сложность | По последним 3 попыткам на текущей сложности: все зачтены и средний ≥ 85 — повысить; зачтено меньше половины или средний < 60 — понизить; иначе оставить |
| Лидеры и отстающие | По среднему баллу среди обучаемых минимум с 2 попытками. Объяснение шаблонное: у лидеров — группы проверок без ошибок, у отстающих — две группы с наибольшей долей ошибок |

## 4.11. Прогноз и проверка «прогноз ↔ факт»

**Методика.**

- Балл занятия — средний итоговый балл обучаемого в нём. Занятия упорядочены по времени.
- Прогноз на следующее занятие — экспоненциальное сглаживание с трендом (метод Хольта):
  коэффициент уровня 0,5, коэффициент тренда 0,3; результат ограничен шкалой 0–100.
- Интервал: ± стандартное отклонение прошлых баллов, но не уже 5 баллов. По одному занятию
  тренда нет, интервал ±15.
- Зона риска: ожидаемый балл ниже порога зачёта или нормативы соблюдаются реже чем в 50 %
  случаев.

**Проверка на истории.** Для каждого обучаемого и каждого занятия, кроме первого, прогноз
строится только по предыдущим занятиям и сравнивается с фактическим баллом. Показываются:

- средняя абсолютная ошибка прогноза;
- та же ошибка у наивного прогноза (среднее прошлых баллов);
- доля случаев, когда факт попал в интервал;
- точечный график «прогноз × факт» с диагональю.

При числе пар меньше 10 интерфейс помечает выводы как предварительные.

**Результат на стенде (29.09.2026).** Сравнено 9 пар. Средняя ошибка метода 29,7 балла против
31,9 у наивного прогноза, факт попал в интервал в 67 % случаев. Истории мало, баллы тестовых
попыток сильно разбросаны (много прерванных попыток с нулевым баллом). Вывод предварительный:
метод не хуже наивного, точность на такой выборке низкая.

## 4.12. Проверка орфографии

- Проверяется текст, введённый обучаемым: описание и адреса карточки, созданной из звонка,
  и комментарии ДДС к решениям и статусам.
- Проверка офлайн в браузере: библиотека nspell с русским словарём Hunspell (dictionary-ru).
  Словарь (около 3,5 МБ) загружается лениво, только на страницах разбора и отчёта, и
  разбирается в отдельном потоке (Web Worker), не блокируя интерфейс.
- Не проверяются: слова с заглавной буквы (имена, названия улиц, аббревиатуры, начало
  предложения), слова короче 3 букв, слова из эталона и названия типов происшествий.
- Результат: «Грамотность ввода» в разборе (число ошибок, подсветка слов, до трёх вариантов
  исправления) и колонка «Орфографических ошибок» в таблице, PDF и CSV занятия. Подпись везде:
  «Автоматическая проверка орфографии, может ошибаться на названиях».
- В балл орфография не входит: сервер описание и комментарии не оценивает.

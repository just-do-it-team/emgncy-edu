## 4.2. Классификатор происшествий

- Единый классификатор происшествий (ЕКП) собран из материалов заказчика: 1283 записи. Он хранится на сервере (`backend/src/s112/incident_classifier_reference.json`) и в интерфейсе (`frontend/src/entities/incident/data/incident-classifier.json`).
- Цепочка: группа → определяющие признаки 1, 2, 3 уровня → итоговый тип происшествия → список оповещения. Комбинация признаков однозначно даёт итоговый тип.
- Список оповещения строится по маршрутам записи с учётом обстоятельств: «Правонарушение», «Пострадавшие», «Газификация», «Нет доступа».
- Главная служба типа всегда входит в список и стоит первой. Пропуск главной службы — критическая ошибка.
- Службу, не попавшую в список автоматически, оператор 112 может добавить вручную. Диспетчер ДДС службы в карточку не добавляет.
- Опросная карта строится из классификатора, а не пишется руками. Сервер сверяет классификацию карточек и эталонов с тем же справочником (`classifier_reference.py`).

| Код | Служба |
|---|---|
| 101 | Пожарная охрана |
| 102 | Полиция |
| 103 | Скорая медицинская помощь |
| 104 | Аварийная газовая служба |

Справочник сервера называет профильные службы «Служба 101» и т. д. Интерфейс показывает названия из классификатора (`frontend/src/shared/config/service-names.ts`).

**Статус карточки** описывает жизнь происшествия целиком: «Зарегистрирована», «Отработана», «Проверена», «Не оповещено», «Отказ», «Не завершено», «Завершена». Статусы «Не оповещено», «Отказ» и «Не завершено» — ошибочные.

**Статус реагирования** описывает ответ одной службы. Клиент строит список доступных переходов по автомату сервера (`backend/src/s112/domain/rules.py`), выбор — не свободный список, а только допустимые на текущем шаге статусы.

Таблица 22 — Автомат статусов реагирования

| Текущий статус | Допустимые переходы |
|---|---|
| Добавлена (`ADDED`) | Не оповещено, Получена службой, Принята, Не принята |
| Не оповещено (`NOT_NOTIFIED`) | Получена службой, Принята, Не принята |
| Получена службой (`RECEIVED`) | Принята, Не принята |
| Не принята (`REJECTED`) | Принята |
| Принята (`ACCEPTED`) | Начало реагирования, Отказ от выполнения работ |
| Начало реагирования (`RESPONSE_STARTED`) | Прибытие, Отказ от выполнения работ |
| Прибытие (`ARRIVED`) | Проведение работ, Отказ от выполнения работ |
| Проведение работ (`WORK_IN_PROGRESS`) | Работы завершены, Отказ от выполнения работ |
| Работы завершены (`WORK_COMPLETED`) | — терминальный |
| Отказ от выполнения работ (`WORK_REFUSED`) | — терминальный |

«Не принята» и «Отказ от выполнения работ» требуют комментария: пустая строка отклоняется сервером с кодом 422. Терминальные статусы закрывают карточку для редактирования.

## 4.4. Роли и позиции 112 / ДДС

- Роли учётных записей — обучаемый, преподаватель, администратор (`STUDENT`, `TEACHER`, `ADMINISTRATOR` в JWT).
- Позиция обучаемого задаётся назначением: `position_code = null` — оператор 112, код службы — диспетчер ДДС этой службы. Один обучаемый тренируется на обеих позициях под одной учётной записью.
- Сценарий бывает индивидуальным (у каждого обучаемого своё рабочее пространство) или с общим рабочим местом, где карточки оператора 112 получают диспетчеры ДДС.
- Диспетчер ДДС принимает или отклоняет карточку по компетенции своей службы и ведёт статусы. Правильность заполнения карточки он не контролирует: ошибка оператора 112 в его оценку не входит.
- Ограничения проверяются на трёх уровнях:
  - маршрут — интерфейс не пускает в чужой раздел и возвращает в свой;
  - экран — действия, недоступные роли, заблокированы с пояснением;
  - сервер — при включённой авторизации ручка отвечает 403.
- Преподаватель правит только свои сценарии и шаблоны и видит только свои занятия. У администратора нет функций изменения оценок и сценариев.

Таблица 23 — Критерии оценки по позициям

| Позиция | Что оценивается |
|---|---|
| Оператор 112 | Критерии C1–C7: классификация, службы, полнота, адрес, тайминг, грамматика, статусы реагирования (`frontend/src/shared/config/criteria.ts`); в балл сервера входят поля эталона |

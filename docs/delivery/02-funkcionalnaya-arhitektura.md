# 2. Функциональная архитектура

Решение состоит из трёх пользовательских контуров поверх общего сервера тренажёра:

| Контур | Для кого | Состав |
|---|---|---|
| АРМ обучаемого | Обучаемый | Обзор назначенных занятий, рабочее место (АРМ-112 или АРМ ДДС), «Мои результаты», «Справка» |
| Кабинет преподавателя | Преподаватель | Обзор, занятия, монитор, сценарии и шаблоны, группы, обучаемые, разбор попытки, аналитика |
| Панель администратора | Администратор | Обзор стенда, мониторинг, пользователи, отчёты, сервисы, резервные копии, обновления, безопасность |

## 2.1. Возможности по ролям

### АРМ обучаемого

| Возможность | Описание |
|---|---|
| Обзор занятий | Список назначенных занятий: окно выполнения, число попыток, роль (оператор 112 или служба ДДС), запуск и продолжение попытки |
| АРМ-112 | Входящий звонок со звуковым сигналом, «Принять», голосовой разговор с виртуальным заявителем (распознавание речи обучаемого и синтез ответа), индикатор «Собеседник отвечает…», «Положить трубку» |
| Карточка происшествия | Заявитель и его статус, телефоны, структурированный и описательный адрес, описание со слов заявителя, тип происшествия по ЕКП с определяющими признаками и опросной картой, автоматический список оповещения (главная служба первой), ручное добавление службы |
| АРМ ДДС | Журнал карточек службы, раскрытие карточки, «Принята / Не принята» с обязательным комментарием при отказе, статусы реагирования строго по автомату переходов, исходящий звонок руководителю бригады |
| Режим подсказок и обучение по АРМ | Пошаговый обзор интерфейса и подсказки на простых уровнях сложности |
| Справка | Памятка «Работа на АРМ-112» с оглавлением; открывается и из АРМ, не прерывая попытку |
| Мои результаты | Попытки с итоговым баллом, зачётом, временем, числом ошибок и комментарием преподавателя; сводка (средний балл, динамика, доля в нормативе 30 с / 3 мин, главные ошибки); рекомендации; перечень расхождений с эталоном |

### Кабинет преподавателя

| Раздел | Возможности |
|---|---|
| Обзор | Идущие занятия, ближайшие занятия, попытки за сегодня с очередью проверки |
| Сценарии | Конструктор сценария: состав из шаблонов звонков и карточек, встроенные карточки, условия подачи (по времени или после действия), процедурная подача из пула шаблонов, обязательные позиции участников, порог зачёта; утверждение, возврат в черновик, архив, копирование; мастер «Сценарий с ИИ»; «Создать процедурный сценарий» по службам, категориям происшествий и сложности |
| Шаблоны | Библиотека шаблонов «Звонок 112», «Карточка 112», «Карточка ДДС» с версиями; редактор эталона (классификация, службы, адреса, статусы реагирования, доклад бригаде, режим проверки каждого поля); генерация шаблонов моделью и проверка черновиков по секциям перед публикацией |
| Занятия | Назначение группе или отдельным обучаемым (одно задание всем или разные), окно дат, число попыток, позиции ДДС; перенос и отмена занятия без попыток; страница занятия с отчётом, PDF и CSV |
| Монитор занятия | Лента тревог по нормативам, таблица или плитки обучаемых с таймером против норматива, журнал действий, режим проектора |
| Разбор попытки | Балл → критерий → поле → момент в журнале и в записи звонка; расшифровка и запись разговора; «Грамотность ввода»; «Верно — подтвердить» или «Исправить» оценку с причиной; переход к следующей попытке на проверке |
| Группы | Создание, переименование, состав, архив; назначение занятия группе |
| Обучаемые | История попыток обучаемого |
| Аналитика | Тепловая карта ошибок, успеваемость с готовностью и рекомендуемой сложностью, время против норматива, лидеры и отстающие с объяснением, прогноз на следующее занятие и проверка «прогноз ↔ факт», CSV |

### Панель администратора

| Раздел | Возможности |
|---|---|
| Обзор | Сводное состояние стенда, последние предупреждения и ошибки |
| Мониторинг | Метрики и временные ряды из Prometheus, цели и алерты |
| Пользователи | Список, создание, смена роли, блокировка |
| Отчёты | Использование, ошибки, нагрузка, доступность, действия пользователей (аудит) |
| Сервисы, резервные копии, обновления | Состояние; управляющие действия отключены на сервере и возвращают отказ с записью в аудит |
| Безопасность | Парольная политика, контроль целостности компонентов |

## 2.2. Основные сценарии

### Подготовка занятия преподавателем

1. Преподаватель открывает «Шаблоны» → «Сгенерировать шаблоны с ИИ» и выбирает основную службу
   (101–104), при необходимости — дополнительные.
2. Модель составляет связанную пару: входящий звонок 112 и карточку ДДС на каждую службу. Шаблоны
   появляются черновиками.
3. Преподаватель проверяет каждую секцию черновика (классификация, адрес, службы, статусы и
   другие): подтверждает, исправляет в редакторе или отклоняет. Опубликовать шаблон можно только
   после проверки всех секций.
4. Из опубликованных шаблонов собирается сценарий: вручную в конструкторе, мастером «Сценарий с ИИ»
   или кнопкой «Создать процедурный сценарий» (пул карточек по службам, категориям и сложности).
5. Перед сохранением фронт перепроверяет состав по свежему списку шаблонов. Деактивированная версия
   подсвечивается с причиной и предложением перейти на актуальную.
6. «Сохранить и утвердить» — сценарий становится доступен для назначения.

### Назначение занятия

1. «Занятия» → «Назначить занятие»: выбрать сценарий, адресата («Группе» или «Обучаемым»),
   позиции (оператор 112 или служба ДДС), окно выполнения и число попыток.
2. Индивидуальный сценарий — отдельное занятие каждому обучаемому. Общее рабочее место — одно
   занятие на всех участников.
3. Занятие появляется у обучаемых в «Обзоре». Пока попыток нет, его можно перенести или отменить.

### Прохождение занятия оператором 112

1. Обучаемый запускает занятие и попадает на АРМ-112.
2. Поступает входящий звонок. «Принять» — начинается голосовой разговор с виртуальным заявителем.
   Реплика обучаемого распознаётся, модель формирует ответ заявителя, ответ озвучивается.
3. Обучаемый заполняет карточку: заявитель, адрес, описание, тип происшествия и признаки.
   Список служб формируется по ЕКП.
4. «Положить трубку» → «сохранить». Карточка создаётся, службы оповещаются, карточка
   привязывается к звонку.
5. «Завершить занятие» — сервер оценивает попытку.

### Прохождение занятия диспетчером ДДС

1. Карточка поступает в журнал службы. Норматив раскрытия — 30 секунд.
2. Диспетчер раскрывает карточку, принимает её или отклоняет по компетенции службы (при отказе
   комментарий обязателен).
3. Первая запись (статус с текстом) — в пределах 3 минут от появления карточки.
4. Диспетчер ведёт статусы реагирования по автомату переходов с комментариями и при необходимости
   звонит руководителю бригады. Голосовой доклад проверяется моделью по смыслу.
5. Занятие завершается, сервер оценивает решение, сроки, статусы и доклад.

### Наблюдение и проверка

1. Во время занятия преподаватель следит за монитором: таймеры против нормативов, тревоги
   «не открыта за 30 с», «нет первой записи за 3 мин», бездействие, прерывание.
2. После завершения попытки попадают в очередь «На проверке». В разборе преподаватель
   подтверждает автоматическую оценку одним кликом или исправляет её с обязательной причиной.
3. Страница занятия даёт сводку, типичные ошибки, отчёт PDF и CSV. «Аналитика» показывает
   успеваемость по группе и периоду, готовность и рекомендуемую сложность следующего занятия.

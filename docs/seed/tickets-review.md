# Стартовая библиотека из билетов — на проверку

Источник — `docs/reference-ui/Билеты.docx`, данные — `docs/seed/tickets.json`. Ничего на сервер не
записано. Подбор типа сделан по классификатору фронта
(`frontend/src/entities/incident/data/incident-classifier.json`), службы посчитаны тем же правилом,
что автоподбор в конструкторе (`resolveServices`) по записи и флагам маршрутизации.

Итого: 32 билета, 96 вызовов, уверенность: высокая — 53, средняя — 40,
низкая — 3. Повторяются вызовы 1.2 = 21.1 и 1.3 = 16.2; ситуация «ДТП, Б/П, Б/Р» встречается
четыре раза с разными адресами.

Как читать таблицу:
- «Тип» — номер записи классификатора и итоговый тип;
- «Службы» — экстренные службы маршрута, главная выделена и стоит первой; «+N городских» — остальные службы
  маршрута (управы, ГКУ «НТУ», ЦУКС и т. п.), их полный список — в `tickets.json`;
- «Уверенность» — оценка подбора типа; «средняя» — рядом указана альтернатива;
- «Чего не хватает» — что нужно дописать методисту для полного эталона. Для всех вызовов, кроме
  перечисленного, не хватает описания со слов заявителя, ответов опросной карты и статуса карточки —
  это в таблице не повторяется.

## Главная служба добавлена по классификатору

Автоподбор служб на фронте (`resolveServices`, `entities/incident/model/classifier.ts`) считает
маршруты с условием «признак не выбран» взаимоисключающими с «признак выбран». У записей, где главная
служба заведена только маршрутом «не выбран» (102 — маршрут 7 «признак Правонарушение или Пострадавшие
не выбран», 104 — маршрут 13 «Газификация не выбрана», 101 — маршрут 0 «Нет доступа не выбран»), выбор
признака, который описывает ситуацию, убирает главную службу из результата.

Службы в `tickets.json` и в таблице посчитаны тем же правилом, что в конструкторе: результат
`resolveServices`, и главная служба записи классификатора (`primary_service`) всегда присутствует и
стоит первой — сервер считает главной первую службу эталона. В вызовах ниже главную вернуло это
правило, а не `resolveServices`; в форме эталона у такой службы пометка «главная служба добавлена по
классификатору». Когда `resolveServices` исправят, список не изменится, а пометка пропадёт. Вопрос
владельцу классификатора — `docs/api/open-questions.md`, «Предложения для АРМ».

## Способ загрузки

Сравнивались два варианта. Реализация — после решения.

| | Скрипт через API от имени преподавателя | Кнопка «Импорт» в разделе «Шаблоны» |
|---|---|---|
| Что делает | читает `tickets.json`, создаёт шаблоны звонков и сценарии «Билет N» через `POST /card-templates`, `/incoming-call-templates`, `/training-scenarios` | загружает `tickets.json`, показывает каждый вызов в редакторе шаблона с подставленными данными; преподаватель правит и подтверждает по одному |
| Проверка человеком | до запуска, по этой таблице | по каждому вызову, в штатной форме эталона |
| Эталон | создаётся сразу, с пробелами из «Чего не хватает» — придётся доправлять новой версией шаблона | заполняется до сохранения; клиентская проверка и 422 работают как при ручном создании |
| Стоимость | небольшой скрипт вне фронта; нужен токен преподавателя и включённый бэк | загрузчик файла, очередь вызовов, переиспользование редактора шаблона; отдельный режим предпросмотра |
| Повторяемость | повторный запуск создаёт дубликаты, нужна проверка по `template_key` | импорт идёт по одному вызову, дубликаты видны в списке |
| Изолированный контур | запускается на стенде один раз | работает в любой инсталляции без консоли |
| Риск | неподтверждённые эталоны попадают в библиотеку как активные шаблоны | медленно: 94 подтверждения |

**Рекомендация — кнопка «Импорт» с подтверждением каждого вызова.** Эталон — это критерий оценки
обучаемого; при средней и низкой уверенности у трети вызовов массовая загрузка создаст активные
шаблоны с неверной классификацией, а исправление — это новая версия шаблона. Импорт через редактор
переиспользует готовую форму и проверку, не требует доступа к консоли стенда и оставляет решение по
каждому вызову за преподавателем. Скрипт оправдан, только если методист заранее вычитает эту таблицу
и заполнит «Чего не хватает» в `tickets.json`.

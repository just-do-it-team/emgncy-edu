# Статус реагирования

Описывает ответ одной службы. Девять значений, переходы строго последовательны.

```
Добавлена (авто)
  └─ Получена службой (авто)
       ├─ Принята ──────────┐
       └─ Не принята ── Принята
                              │
              Начало реагирования
                     └─ Прибытие
                          └─ Проведение работ
                               ├─ Работы завершены      (терминальный)
                               └─ Отказ от выполнения работ (терминальный)
```

Правила, нарушение которых — дефект:

- из «Не принята» единственный доступный переход — «Принята»;
- «Не принята» и «Отказ от выполнения работ» требуют обязательного комментария,
  без него сохранение блокируется;
- терминальные статусы закрывают карточку для редактирования;
- выбор статуса — не свободный список, а строго доступные на текущем шаге.

## Фактический автомат бэкенда

Схема выше описывает предметную область по памятке АРМ-112. Реализация
(`backend/src/s112/domain/rules.py:4-40`) содержит **десять состояний, а не девять**:
между «Добавлена» и «Получена службой» добавлено `NOT_NOTIFIED`, а `WORK_REFUSED`
достижим из четырёх состояний, а не только из «Проведение работ». Клиент строит список
доступных переходов по этой таблице, а не по схеме выше.

| Текущий статус | Допустимые переходы |
|---|---|
| `ADDED` | `NOT_NOTIFIED`, `RECEIVED`, `ACCEPTED`, `REJECTED` |
| `NOT_NOTIFIED` | `RECEIVED`, `ACCEPTED`, `REJECTED` |
| `RECEIVED` | `ACCEPTED`, `REJECTED` |
| `REJECTED` | `ACCEPTED` |
| `ACCEPTED` | `RESPONSE_STARTED`, `WORK_REFUSED` |
| `RESPONSE_STARTED` | `ARRIVED`, `WORK_REFUSED` |
| `ARRIVED` | `WORK_IN_PROGRESS`, `WORK_REFUSED` |
| `WORK_IN_PROGRESS` | `WORK_COMPLETED`, `WORK_REFUSED` |
| `WORK_COMPLETED` | — терминальный |
| `WORK_REFUSED` | — терминальный |

Обязательность комментария реализована для `REJECTED` и `WORK_REFUSED`
(`rules.py:48-51`): пустая или пробельная строка отклоняется с `422`.

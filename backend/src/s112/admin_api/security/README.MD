# Вкладка «Безопасность»

Вкладка не дублирует роли и аудит. Роли назначаются во вкладке «Пользователи»,
а события аудита показываются в «Отчёты → Действия пользователей».

## Обзор

`GET /api/v1/admin/security/overview` возвращает фактически реализованные меры и
известные риски. Статусы: `enabled`, `warning`, `not_configured`. До появления
общей авторизации пункт `authentication` намеренно остаётся `not_configured`.

## Парольная политика

- `GET /api/v1/admin/security/policy`;
- `PATCH /api/v1/admin/security/policy`.

Изменяемые поля: `password_min_length` (8–128), `require_uppercase`,
`require_lowercase`, `require_digit`, `require_special`. Политика применяется к
новым паролям при создании пользователя. Изменение записывается в аудит.

## Контроль целостности

`GET /api/v1/admin/security/integrity` проверяет подключение к основной БД и состояние
обязательных целей Prometheus. Результат содержит общий статус и отдельные
проверки. Это проверка доступности компонентов, а не криптографическая проверка
файлов на хосте.

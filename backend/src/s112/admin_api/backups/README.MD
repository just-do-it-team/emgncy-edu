# Вкладка «Резервное копирование»

- `GET /api/v1/admin/backups/status` — конфигурация, расписание, последнее успешное
  выполнение и причина блокировки действий;
- `GET /api/v1/admin/backups` — список доступных резервных копий;
- `POST /api/v1/admin/backups/actions/create` — ручное создание;
- `POST /api/v1/admin/backups/{id}/actions/restore` — восстановление.

На текущем демонстрационном стенде хранилище и расписание не настроены, поэтому
список пуст, а создание и восстановление возвращают `423 operation_disabled`.
Обе попытки записываются в аудит. Frontend должен показывать безопасный режим и
не изображать отсутствие копий как ошибку загрузки.
